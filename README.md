# Портфолио

Статический одностраничный сайт. Ноль зависимостей, ноль сборки — открывается двойным кликом по `index.html`.

```
index.html      главная: оффер, работы, отзывы
brief.html      бриф-опросник для клиента
css/style.css   стили обеих страниц и обе темы
js/main.js      главная: тумблер темы, появление секций, год
js/brief.js     бриф: сборка текста, черновик, копирование
assets/         превью работ и favicon
```

## Что подставить под себя

### 1. Ник в Telegram

Сейчас везде стоит заглушка `https://t.me/username`. Заменить все вхождения разом:

- в VS Code: `Ctrl+Shift+H` (поиск по всем файлам), найти `t.me/username`, заменить на `t.me/ваш_ник`, нажать «Заменить всё».

Всего 8 мест: 6 в `index.html` (шапка, hero, финальный CTA, футер, плавающая кнопка, блок `application/ld+json`) и 2 в `brief.html` (шапка и кнопка отправки брифа).

### 2. Имя и заголовок

- `<title>` и `<meta name="description">` в `<head>` — это то, что видно во вкладке и в поиске.
- Блок `og:title` / `og:description` — то, как ссылка развернётся при отправке в Telegram.
- `<h1>` в секции `.hero` — главный оффер. Чем конкретнее (что делаете, за какой срок, что получает клиент), тем лучше.
- Цифры в блоке `.facts` — три факта под оффером.
- Имя в `.logo` в шапке и в футере.

### 3. Работы

Секция `<section id="works">`, четыре блока `<article class="card">`. В каждом меняется:

| Что | Где |
|---|---|
| Ссылка на проект | `href` у `<a class="card-link">` |
| Картинка превью | `src` у `<img class="card-media">` |
| Название | `<h3>` |
| Описание | `<p>` под заголовком |
| Технологии | `<li>` внутри `<ul class="tags">` |

Чтобы добавить пятую работу — скопируйте любой `<article class="card">…</article>` целиком и вставьте следом. Сетка сама перестроится.

**Превью.** Сейчас лежат заглушки `assets/work-1.svg` … `work-4.svg`. Замените их своими скриншотами:

- пропорции 16:9, оптимальный размер 1280×720;
- формат `.webp` (легче) или `.jpg`;
- после замены поправьте `src` и `alt` у `<img>`, а `width="640" height="360"` можно оставить — это только пропорции, картинка тянется по ширине карточки.

### 4. Отзывы

Секция `<section id="reviews">`, три блока `<article class="review">`: текст отзыва, имя, род занятий. В `<span class="avatar">` — одна буква, она рисуется кружком автоматически.

### 5. Почта

В финальном CTA стоит `moskalevnikolaj861@gmail.com` — поменяйте или удалите строку `<p class="cta-note">`.

### 6. Превью ссылки в Telegram (опционально)

Положите картинку `assets/og.png` размером 1200×630 и добавьте в `<head>`:

```html
<meta property="og:image" content="https://ваш-домен/assets/og.png">
```

Путь обязательно абсолютный — относительный Telegram не поймёт.

## Бриф-опросник

Отдельная страница [brief.html](brief.html) — ссылка на неё стоит в шапке главной и в финальном блоке.

**Как это работает у клиента.** Он отмечает подходящие варианты (заполнять всё необязательно), жмёт «Собрать бриф» — из ответов складывается текстовое ТЗ. Кнопка «Скопировать и открыть Telegram» кладёт текст в буфер и открывает чат с вами: клиенту остаётся вставить и отправить. Ответы автоматически сохраняются в браузере клиента, так что страницу можно закрыть и вернуться позже. Никуда, кроме его же браузера, данные не уходят.

**Как менять вопросы.** Каждый вопрос — это блок `<div class="field">` с двумя атрибутами:

- `data-label` — как строка назовётся в готовом брифе;
- `data-type` — `text` (поле ввода), `radio` (один вариант) или `checkbox` (несколько).

Скрипт сам подхватит новый вопрос, если у блока есть оба атрибута — трогать `js/brief.js` не нужно. Названия разделов в готовом тексте берутся из `<h2>` соответствующей секции.

Добавить вариант ответа — скопируйте соседний `<label class="chip">` или `<label class="opt">` и поменяйте `value` (он и попадёт в текст брифа) вместе с видимой подписью. У чекбоксов значения `value` должны быть уникальными на всю страницу — иначе черновик восстановится неправильно.

Убрать целый раздел — удалите его `<section class="brief-section">` и соответствующую ссылку из `<nav class="brief-nav">`.

## Цвета

Все цвета живут в двух блоках в начале `css/style.css`: `:root` — светлая тема, `:root[data-theme="dark"]` — тёмная. Чтобы сменить акцент, достаточно поправить `--accent`, `--accent-hover` и `--accent-soft` в обоих блоках.

Тема по умолчанию берётся из системных настроек посетителя, ручной выбор сохраняется в `localStorage`.

## Деплой на GitHub Pages

```bash
cd portfolio
git init
git add .
git commit -m "Портфолио"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git
git push -u origin main
```

Дальше в репозитории: **Settings → Pages → Source: Deploy from a branch → Branch: `main`, папка `/ (root)` → Save.**

Через минуту сайт будет на `https://ВАШ_ЛОГИН.github.io/ВАШ_РЕПОЗИТОРИЙ/`.

Хотите адрес вида `https://ВАШ_ЛОГИН.github.io/` без хвоста — назовите репозиторий `ВАШ_ЛОГИН.github.io`.

Свой домен подключается там же, в **Settings → Pages → Custom domain**; у регистратора домена нужно прописать CNAME на `ВАШ_ЛОГИН.github.io`.

Файл `.nojekyll` в корне нужен, чтобы GitHub не пытался прогонять сайт через Jekyll — не удаляйте его.

## Локальная проверка

Достаточно открыть `index.html` двойным кликом. Если хочется поднять нормальный локальный сервер:

```bash
py -m http.server 8000
```

и открыть `http://localhost:8000`.
